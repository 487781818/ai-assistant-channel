# 给 AI 助手在自家电脑里开一条受控通道

> 不用云端浏览器、不用装扩展：让 AI 助手直接在**你自己的电脑、你自己的网络出口**里干活，
> 还能自己给软件升版本。本文是一次真实落地的完整复盘：架构、接口、安全模型、
> 自更新机关，以及三个用真金白银（和一整个下午）换来的坑。
>
> 文中所有地址、令牌、设备名均为占位符。示例代码在 `example/`，可独立运行。

---

## 1. 为什么另起炉灶：三条死路

想让 AI 助手操作你电脑里的浏览器，通常有三条路，我全试过：

| 路线 | 死因 |
|---|---|
| 云端浏览器（助手服务商提供） | 出口 IP 是共享机房 IP，被无数人用过，风控眼里天生可疑；也进不了你的内网和本机应用 |
| 给真 Chrome 装助手扩展 | 扩展只服务于「在那个 Chrome 里发起的对话」；你的对话如果活在别的应用里，它根本看不见 |
| 把扩展装进 Electron 应用 | Electron 没有扩展系统；社区兼容层只支持 API 子集，而主流助手扩展依赖 sidePanel、identity 和与厂商服务的远程握手，改不了、也等不到适配版 |

结论：与其求别人开门，不如**在自己的应用里给助手留一扇带锁的门**。

## 2. 总体架构

```
┌────────────────┐   Tailscale 私网    ┌──────────────────────────────┐
│  AI 助手        │ ─────────────────▶ │  你的电脑                     │
│ （另一台机器）   │   直连 tailnet IP   │  Electron 应用               │
│                │   Header: x-oc-token│  ├─ 通道服务 :5175（令牌校验） │
│  curl / HTTP   │                     │  ├─ 业务接口（下单等）         │
└────────────────┘                     │  ├─ 助手浏览器（独立分区）     │
                                       │  └─ 电脑管理（独立开关）       │
                                       └──────────────────────────────┘
```

三个设计决定：

1. **通道长在应用里，不另开进程。** 应用本来就持有登录态、页面和业务逻辑，
   通道只是把这些能力以 HTTP 形式开出来，复用现成的执行器，一行重复代码都不用写。
2. **网络只走私网。** 两台机器都装 Tailscale（或同类 WireGuard 组网），
   服务绑定在 tailnet 可达的地址上，公网完全不可见。再加一道随机令牌，双保险。
3. **权限分级，开关在用户手里。** 通道总开关、电脑管理子开关互相独立；
   令牌可一键重置；关掉组网软件，整条路立即死透。

## 3. 安全模型

- **令牌**：48 位十六进制随机串，服务端用 `crypto.timingSafeEqual` 做恒定时间比较，
  请求头 `x-oc-token` 不对就 401。令牌只存在于应用本地配置，不进任何仓库。
- **审计流水**：每一次写操作和每一次电脑管理调用，先记账再执行（或执行后立即记账），
  内存环形缓冲 + 落盘 `channel-audit.log` 双份，应用内可查。
- **电脑管理默认关**：装好之后是用户亲手打开的；关掉它，`/pc/*` 全部 403，
  但业务接口和浏览器接口不受影响。
- **助手侧纪律**（写进教程是因为这决定了这套东西能不能长期用）：
  低频、拟人节奏操作；只做被授权的事；破坏性操作（删文件、杀进程）先报数、再动手。

## 4. 接口一览

通道服务（端口 5175，全部需要令牌）：

| 方法与路径 | 作用 |
|---|---|
| `GET /status` | 版本、账号数、忙碌情况、电脑管理开关、浏览器数量 |
| `GET /accounts` / `POST /jobs` / `GET /jobs/:id` | 业务接口：列出应用内账号、向某个账号下单、查任务状态（按你的应用业务替换） |
| `GET /browsers` | 列出助手浏览器槽位 |
| `POST /browsers/:id/open` `{url}` | 在该槽位打开页面，等加载完成 |
| `GET /browsers/:id/text` | 提取页面正文（innerText，上限截断） |
| `POST /browsers/:id/click` `{selector 或 text}` | 按选择器或可见文字点击 |
| `POST /browsers/:id/type` `{selector?, text, submit?}` | 真实鼠标点击聚焦 + 输入 + 回读校验（见第 7 节的坑） |
| `GET /browsers/:id/shot` | 页面截图（PNG，见第 7 节的坑） |
| `POST /browsers/:id/back` / `forward` | 前进/后退 |
| `GET /pc/info` | 主机名、系统、用户、下载目录 |
| `POST /pc/exec` `{cmd, timeoutMs}` | 以应用的用户身份跑一条命令，回传 stdout/stderr/退出码 |
| `GET /pc/ps` / `POST /pc/kill` `{pid}` | 进程列表 / 结束进程 |
| `POST /pc/open` `{path}` | 打开程序、文件或网址 |
| `GET /pc/list?dir=` / `GET /pc/file?path=` | 列目录 / 取文件 |
| `POST /pc/push` `{name, dir?, dataBase64}` | 把文件推到电脑上（默认进下载目录） |

助手侧调用示例（两台机器在同一私网即可直连）：

```bash
curl -H "x-oc-token: <YOUR_TOKEN>" http://<TAILNET_IP>:5175/status
curl -X POST -H "x-oc-token: <YOUR_TOKEN>" -H "Content-Type: application/json" \
  -d '{"url":"https://example.com"}' http://<TAILNET_IP>:5175/browsers/main/open
```

## 5. 助手浏览器：每个助手一个槽位

- 每个槽位 = 一个独立的 `WebContentsView` + 独立持久分区 `persist:ocb-<id>`，
  登录态互不串味；谁的浏览器谁用，天然避免两个助手抢同一页。
- 槽位在侧栏可增删改名（示例上限 6 个）；闲置槽位不创建视图，被调用时才懒加载唤醒。
- 关键收益：**出口 IP 是用户家里的宽带，环境是用户的真机**，
  和用户本人日常使用完全一致——这是它比云端浏览器安全的根本原因。
  剩下的风险只在操作节奏，所以助手侧必须低频拟人。

## 6. 自更新机关：助手能自己给软件升版本

通道一旦能推文件、能跑命令，就可以让助手**自己完成升级**，用户不用再手动装包：

1. 助手把新版 `app.asar` 推到 `resources\app.asar.new`（先当备胎，不动正在用的）；
2. 再推一个潜伏脚本 `self-update.bat` 并 detached 启动它（脚本模板见 `self-update/`）；
3. 脚本等 3 秒 → 结束主程序与桥接进程 → 把 `.new` 覆盖为正式 `app.asar` → 重新拉起应用 → 自删；
4. 通道随应用重启自动恢复（开关与令牌都是持久化的），助手轮询 `/status` 看到新版本号即确认成功。

要点：脚本必须**脱离主进程独立存活**（`Start-Process` 拉起），否则杀主程序时它会陪葬；
脚本内容保持纯 ASCII，避免 Windows 按本地代码页误读。

## 7. 三个大坑（本教程最值钱的部分）

### 坑一：没显示过的视图，不绘制、也不布局

症状：对一个从没在屏幕上显示过的 `WebContentsView` 截图，得到空图；
读页面元素的 `getBoundingClientRect()`，全是 `0×0`、坐标 `0,0`；
往输入框打字，找不到可点的位置。

原因：Chromium 对不可见视图不排帧、不做布局——`setVisible(false)` 的页面
在合成器眼里不存在。把视图挪到屏幕外（-32000,-32000）保持 visible 也**没用**，
实测照样不画。

解法（`ensurePainted`）：需要几何或画面的操作执行前，
先把目标视图 `setVisible(true)`，**再把用户正在看的那一页重新置顶盖回它上面**——
视图保持 visible 在底下继续绘制，用户屏幕上什么都看不见；操作完再熄灯。
点亮后别傻等固定毫秒数：用双 `requestAnimationFrame` 等页面真排出一帧，
慢机器上冷排版可能超过 600ms，固定睡眠会翻车。

### 坑二：同名孪生元素——第一个匹配是藏起来的

症状：页面明明画得出来、截图里搜索框好端端的，
但 `document.querySelector('#kw')` 命中的元素几何恒为 `0×0`，打字永远失败。

原因：某些大站的新版首页里**同 id/同选择器的元素有两份**，
第一份是隐藏的（给另一种形态的界面预留），真正可见的是后面那份。
`querySelector` 只取第一个，于是永远在跟空气交互。

解法：探针、赋值、回读三处统一改成**遍历 `querySelectorAll`，
挑第一个真正可见的**（宽高 > 0 且 `display/visibility` 正常）。
点击、聚焦、回读校验必须用同一套挑选逻辑，否则点的是 A、读的是 B。

### 坑三：PyInstaller 单文件程序被强杀，会留下 126 MB 的孤儿目录

症状：用户 Temp 目录无声无息攒了 1.1 GB，里面是 9 个 `_MEI*` 文件夹，每个 126.5 MB。

原因：PyInstaller onefile 程序每次启动把自己解压到 Temp 的 `_MEI*` 目录，
正常退出自删；**被强杀（taskkill /F、崩溃）就留一个孤儿**。
偏偏升级脚本、自更新机关杀的都是它——升一次版，留一个。

清理法（脚本见 `tools/cleanup-mei-orphans.ps1`）：正在跑的那个不能删——
认领办法是比对进程启动时刻与目录创建时刻（同一秒即本人），其余全删。
长效解法是升级流程里顺手扫孤儿，或改用 onedir 打包（不解压、无此问题）。

## 8. 示例代码

`example/` 是一个可独立运行的最小实现（Electron）：

- 通道服务：令牌校验、`/status`、浏览器五件（open/text/click/type/shot）、`/pc/exec`（子开关控制）；
- 两块修复都在里面：`ensureBrowserPainted`（坑一）与 `pickVisible`（坑二）；
- 控制面板：通道开关、电脑管理开关、令牌显示与重置、流水查看。

运行：

```bash
cd example
npm install
npm start
```

启动后在面板里打开「远程通道」，把令牌发给你的助手，它就能从私网另一端敲门了。

## 9. 边界

- 这套通道的权限 = 应用所在用户的权限。它是为「用户完全信任自己的助手」设计的，
  令牌给谁，谁就能用；不要把令牌发到任何公开场合。
- 它不解决账号本身的风控：助手操作节奏太机器，一样会触发平台的自动化检测。
- 删文件、杀进程这类动作，助手应先报数再动手——这条是纪律，不是功能。
